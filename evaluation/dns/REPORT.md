# DNS detector evaluation

Malicious traffic: independent text and file transfers generated by [zrckr/dns-tunnel](https://github.com/zrckr/dns-tunnel) client `dns_ask`, source commit `93cfb4a2ff3c53c9e32142ea518cbbcaf7dacf7d`; 100 seeded runs, each with a distinct input and source IP. Input PCAP SHA-256: `f326de01689bf8289ee7ea2e149564ec0699195a0592b66aa75e42f8b9cc6a43`. Benign traffic: 100 locally generated DNS sessions across ordinary, service discovery, and cache-busting names.

## Tool relevance and research connection

The selected `zrckr/dns-tunnel` tool constructs DNS queries for text and file transfer. Its packet builder permits 100 reproducible offline transfer sessions. Its README describes it as a local-network simulation.

[Chen et al., *Computers & Security* 104 (2021), 102095](https://doi.org/10.1016/j.cose.2020.102095) generated DNS traffic with eight covert-channel tools, including iodine, dnscat2, and dns2tcp. [Zheng et al. (2025)](https://www.joca.cn/EN/10.11772/j.issn.1001-9081.2024070972) evaluate DNS tunnel tools and emphasize reproducible sample generation. Neither paper tests `zrckr/dns-tunnel`. The saved iodine capture is a research-aligned reference excluded from these 100 sessions.

## Method

Offline packet replay through the production packet parser and detector functions. Each class has fresh detector state. A session is one source/destination flow (also grouped by apex for DNS), split after more than 60 seconds of inactivity. A session is detected if any of its packets emits an alert. `sessions.csv` is the primary evaluation; `results.csv` retains packet-level diagnostics and messages. This tests alerting, not live capture or blocking.

## Interpretation

The external tool produced 100 independent transfers, each with its own source and run-specific domain. A transfer counts as detected when at least one of its queries alerts. The session scenario table separates text and file transfers.
Short text transfers may stay below the length and entropy thresholds and make too few queries for the volume rule. File transfers can have multiple queries, but these are one datapoint per transfer.
The 6 missed transfers in this run are single-query text sessions with name lengths [34, 38]; none reaches the eight-unique-query volume threshold.

All 20 cache-busting sessions are false positives from `DNS_LONG_QNAME`; ten ordinary ten-query bursts are false positives from `DNS_TUNNEL_VOLUME`. The benign traffic is synthetic, with different one-, two-, and ten-query sessions; the packet and session alert rates describe this designed mix, not deployment-wide rates.

## Limits

The replay calls the production parser and detector on packets, but does not exercise live sniffing, dropped packets, routing, gateway logs, or blocking. The benign traffic is synthetic and the malicious traffic comes from one tool per protocol; broader traffic sources and more tools are needed before estimating field precision or recall.
